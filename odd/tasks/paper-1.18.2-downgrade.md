# Paper 1.18.2 / Java 21 downgrade
Target: Paper 1.18.2 API, compiled with JDK 21 to Java 17 bytecode, all features preserved.

## Specs
S1 (user request, verbatim): "Downgradea el plugin y la version de java del
 servidor para que compile con java 21 y pueda
 correr en un servidor de 1.18."
S2: The build must compile with a Java 21 toolchain (`org.gradle.java.installations` / `toolchain languageVersion 21`) and must not block a Java 21 toolchain from being used.
S3: The produced plugin JAR must load on a Paper 1.18.x server. Concretely: `paper-plugin.yml` must be replaced by a `plugin.yml` with `api-version: "1.18"`, `void Generation of Paper's LifecycleEvents/Brigadier command API` (not present on 1.18.2), no class or method introduced after 1.18.2, and Java 17 bytecode (`options.release = 17`) so it also runs on a Java 17 JVM.
S4: All existing player-facing behavior stays identical: same command names, arguments, aliases, permissions, message keys and message text, same tab completion, same persistence formats (spawns/kits JSON, death-messages.yml, blocked-commands.yml, messages.yml, SQL stats).
S5: Every dependency must be usable on a 1.18.2 runtime: Paper API 1.18.2, PlaceholderAPI 1.18-era, MockBukkit v1.18 for the test harness, and no library compiled against 1.20+/1.21-only API (this removes `mcdev-utils`).
S6: `./gradlew build` (compile + full test suite + shadowJar) must pass, and `./gradlew runServer` must boot Paper 1.18.2 with the plugin enabled.
S7: Documentation that names the old target (AGENTS.md, README.md) must describe the new one (plugin.yml instead of paper-plugin.yml, Bukkit command API instead of the Brigadier API, 1.18.2 runServer).
